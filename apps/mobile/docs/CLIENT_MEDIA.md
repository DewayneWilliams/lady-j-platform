# Client media

Owners open the media library from Clients, an individual contact, or an appointment card. An appointment must belong to the contact’s registered account; otherwise media can be stored as a standalone contact record. Upload and capture accept up to ten items per batch. Photos are resized to a 2048px long edge and JPEG-compressed; previews are at most 360px wide. Video is limited to three minutes and 50 MB after preparation, with local compression and a separately stored poster. The browser explicitly discloses original-video fallback when compression is unsupported. Native compression requires the configured compressor module in a Publishing build. No device-library save API is used. Native generated caches and web blob URLs are released after successful uploads or closing the upload screen.

The virtualized grid loads 60 records per page, with server-side search, date/type/service/appointment/album/favorite/access filters. Ordering is persisted per account and device. Upload time is server-generated and immutable; the display date is editable and defaults to the salon-local date. Album descriptions and captions are visible when shared. Notes remain owner-only. Select two photos to compare them; photo viewers provide fit/zoom controls and panning, with native iOS pinch zoom. Videos use native playback controls without a persistent media cache.

## Access

`lj_client_media`, `lj_media_albums`, `lj_media_consent` and `lj_media_audit` have RLS. Authenticated owners can read their management tables, and all app writes use checked owner RPCs. Client reads use a sanitizing RPC; they cannot directly read metadata, notes, audit records or write media. Private storage policies authorize each exact reserved object path. Uploading cannot overwrite finalized files or use an unreserved path. Upload reservation keys make retries idempotent.

Items are owner-only until explicitly approved. Sharing also requires recorded consent and the contact’s `customer_id` to match the authenticated client. A shared album contains only individually approved media; its cover also passes that check. Consent revocation clears every item’s access flag, and granting consent again does not reshare anything. Changing the contact’s account link also clears consent and access. Clients can withdraw their own consent but cannot grant it themselves. Capture/sharing consent is distinct from marketing permission and the existing service agreement. Record the consenting guardian’s name for a minor.

All viewing URLs expire after 60 seconds. New URLs are denied immediately upon revocation; an issued URL or already downloaded copy cannot be recalled. Client lists recheck every 20 seconds and on foreground/reconnection. UI image caches are disabled. Owner audit records include sharing, consent, metadata, album and deletion events with authenticated actor IDs and server timestamps.

Deletion first hides metadata and revokes visibility, then removes originals and previews. Tombstones preserve the paths until storage cleanup is confirmed. Interrupted deletion is detected when reopening the library; “Finish storage cleanup” retries removal. The footer also provides cleanup for deleted files. Interrupted uploads remain marked “Retry upload”; reopening lets the owner reselect the source, or select and delete an incomplete item. Files are processed sequentially to keep mobile memory and bandwidth bounded.

## Deployment and verification

Migrations 027–031 configure the tables, RPCs, private bucket and policies on the Draftbit-managed development branch. Use Supabase → Deploy to Production to publish these changes. Native builds use Publishing to include the image picker/compressor configuration. No Edge Function or external media provider is required.

`supabase/tests/client_media.sql` runs transactionally and rolls back its synthetic identities, metadata and storage records. It exercises storage-path enforcement, owner/client/anonymous authorization, isolation, consent, private covers, metadata sanitization, idempotent reservation, client withdrawal and deletion. Live browser testing should additionally cover photo/video upload and retry, poster creation, video playback, metadata edits, album covers, zoom/comparison, persisted ordering, deletion cleanup, client account navigation and revoked signed-link issuance. Camera hardware and native compression must also be exercised on a compatible native simulator/device build.
